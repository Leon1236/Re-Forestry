# mods.db — Database & Repo Inventory (Phase 0–2 findings)

Generated by querying the uploaded `mods.db`. Every fact below is verified against actual file contents in the database, not assumed.

## Schema

- `repos(name PK, source_file, loader_hint, file_count, total_bytes)` — one row per ingested GitHub repo.
- `files(id PK, repo, path, language, content, size)` — one row per file; `UNIQUE(repo, path)`.
- `files_fts` — FTS5 virtual table over `files(path, content)`, tokenizer `unicode61` with `_.$` added as token characters (so tokens like `forestry.api` or `alveary_heater` survive tokenization intact). Content-linked to `files` via `content_rowid='id'`.

Total: 8 repos, 38,845 files. DB file is ~92MB.

**Operational note:** the `/mnt/user-data/uploads` mount is read-only, and SQLite needs to open journal/lock files next to the .db even for reads — so `sqlite3.connect()` fails in place. Copy the file to a writable path first (`cp mods.db /home/claude/work/`). Also: the `sqlite3` CLI binary isn't installed in this environment — use Python's stdlib `sqlite3` module instead.

### Canonical queries
```sql
-- list files in a repo under a path prefix
SELECT path, language, size FROM files WHERE repo = ? AND path LIKE ? ORDER BY path;

-- fetch one file's content
SELECT content FROM files WHERE repo = ? AND path = ?;

-- full-text search across all repos
SELECT f.repo, f.path, snippet(files_fts, 1, '[', ']', '...', 10)
FROM files_fts JOIN files f ON f.id = files_fts.rowid
WHERE files_fts MATCH ? ORDER BY rank;
```

## Key finding: the modern fork lineage is the better porting base, not the 1.12.2 original

The original repo predates the 1.13 "flattening": `.lang` instead of JSON, unflattened texture paths, `mcmod.info`, an old registry/recipe system. Porting that straight to Minecraft 26.2/Fabric means reimplementing nearly every asset and registry convention from zero.

`ForestryCE` and `Immersive-Forestry` already did that modernization — **while keeping the original `forestry` modid and the original `forestry.<module>` package layout** (confirmed: both ship the identical `src/main/java/forestry/api/README.md` at the same path). Their assets already use flattened paths and JSON lang (`assets/forestry/lang/en_us.json`, `assets/forestry/textures/block/...`), and their recipes are modern Forge JSON. That's a far smaller gap to Fabric 26.2 than the original — while still satisfying "same folder paths and naming convention," since the forks preserve that convention themselves.

- Current dev tooling: Loom 1.17, Gradle 9.5.1. Current stable Fabric Loader: 0.19.3.
